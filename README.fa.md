# گریست دسکتاپ فارسی

این نسخه از هستهٔ ثابت‌شدهٔ Grist Desktop و نسخهٔ ثبت‌شدهٔ لایهٔ فارسی مخزن
[`grist-core-fa`](https://github.com/AliMalakoo/grist-core-fa) استفاده می‌کند. رابط دسکتاپ
به‌صورت پیش‌فرض فارسی است؛ تنظیم صریح زبان حساب یا کوکی بر پیش‌فرض اولویت دارد. فونت
Vazirmatn در خود برنامه قرار می‌گیرد و به اینترنت نیاز ندارد. کدهای ویرایشگر همچنان فونت
تک‌عرض خود را حفظ می‌کنند. ترجمه، راست‌به‌چپ و تاریخ جلالی محدودیت‌های ذکرشده در README
مخزن لایهٔ فارسی را دارند. زبان سند را برای تاریخ سلول‌ها جداگانه روی `fa-IR` بگذارید.

## ساخت فایل نصب ویندوز ۶۴ بیتی

این workflow برای هر Pull Request نیز اجرا می‌شود. در صفحهٔ Pull Request می‌توانید اجرای
**Build Persian Windows installer** را باز کنید و پس از موفقیت، artifact را از همان اجرا بگیرید.

برای اجرای دستی، پس از ادغام این workflow در شاخهٔ پیش‌فرض مخزن (شرط GitHub برای اجرای دستی)،
از **Actions → Build Persian Windows installer →
Run workflow** همین شاخه را انتخاب کنید. پس از موفقیت، از صفحهٔ همان اجرا artifact به نام
`grist-desktop-fa-windows-x64` را بگیرید؛ فایل ZIP دانلودشده حاوی فایل نصب `.exe` است.
این فایل امضای دیجیتال ندارد و ممکن است Windows SmartScreen هشدار بدهد. این workflow
به‌روزرسان خودکار نسخهٔ اصلی را به‌صورت پیش‌فرض خاموش می‌کند تا نسخهٔ فارسی با نسخهٔ
غیرفارسی جایگزین نشود. این نسخه شناسهٔ نصب نسخهٔ اصلی را حفظ می‌کند و ممکن است جای آن نصب شود؛
از داده‌ها پیش از نصب یا ارتقا پشتیبان بگیرید.

برای ساخت دستی روی ویندوز، پیش‌نیازهای README اصلی و Node 22، Yarn 1 و Python 3.11 را
نصب کنید، Git را با امکان ساخت symlink اجرا کنید و سپس:

```bash
git submodule update --init --recursive
yarn install --network-timeout 300000 --ignore-optional --frozen-lockfile
yarn run setup
yarn run build
yarn run electron --win nsis --x64
```

نصب‌کننده در `dist/` ساخته می‌شود. آماده‌سازی، patch لایه را فقط در صورت سازگاری با
هسته اعمال می‌کند و فایل‌های فونت دارای مجوز OFL را از `localization/fonts/` کپی می‌کند.
لایهٔ فارسی با شمارهٔ commit در `localization/grist-core-fa/REVISION` ثبت شده است.
تغییر نسخهٔ هسته یا لایه نیازمند بررسی مجدد سازگاری است؛ برای بازسازی از هستهٔ تمیز،
ابتدا تغییرات و فایل‌های شخصی آن را پشتیبان بگیرید، سپس submodule را به نسخهٔ ثبت‌شده
برگردانید و فایل state و فایل‌های تولیدشده را حذف کنید. هرگز تغییرات شخصی را بدون پشتیبان
پاک نکنید.
